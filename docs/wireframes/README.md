# Todo List Lo-fi 와이어프레임

`index.html`을 브라우저에서 열면 모든 화면의 JSON과 HTML을 선택할 수 있습니다.

## 결과물

- Desktop: 1440 × 960px, 6개 화면
- Mobile: 375 × 1440px, 7개 화면. 전체 구조를 검토할 수 있도록 세로 캔버스를 길게 잡았습니다.
- 화면마다 `{name}.wireframe.json`과 `{name}.wireframe.html` 한 쌍을 제공합니다.
- 상태: 목록, 등록, 수정, 삭제 확인, 빈 목록, 검색 결과 없음. 모바일에는 사이드바 펼침 상태를 추가했습니다.
- HTML은 스킬의 기본 템플릿에 해당 JSON을 삽입해 생성했습니다. 생성된 미리보기에만 회색 변환과 시스템 글꼴을 적용했습니다. 스킬 원본은 수정하지 않았습니다.
- 실제 Todo 앱이 아닌 구조 검토용 화면입니다. React 소스, 서버, 데이터 저장 기능은 생성하지 않았습니다.
- 목록 항목에는 현재 상태를 표시하는 `완료/미완료`, `수정`, `삭제` 버튼이 있습니다. 상태 버튼 클릭 시 완료와 미완료가 서로 전환되고 요약 개수와 JSON 패널도 갱신됩니다. 수정·삭제 버튼은 같은 기기 크기의 해당 와이어프레임으로 이동합니다.
- 상태 변경은 현재 미리보기 메모리에만 반영되며 새로고침하면 초기 예시로 돌아갑니다. 유지할 변경은 JSON 저장·다운로드 기능으로 내보낼 수 있습니다. 수정·삭제 화면 이동은 예시 화면 탐색이며 선택한 항목을 저장·삭제하는 기능은 아닙니다.
- 모바일 목록은 내용과 완료·수정·삭제 버튼을 한 행에 배치합니다. 내용만 줄바꿈하며 버튼은 높이 32px, 글자 12px, 좌우 패딩 6px, 버튼 간격 4px로 축소합니다. 데스크톱 버튼은 기존 44px 높이를 유지합니다.
- 목록의 `검색·필터 숨기기` 버튼은 검색과 상태 필터를 함께 접습니다. 접은 뒤에는 `검색·필터 표시`로 바뀌며 다시 누르면 같은 내용을 펼칩니다. 접기·펼치기는 목록 데이터와 필터 정의를 변경하지 않습니다.

## 7단계 설계 판단

1. **구조 우선:** 브랜드 컬러와 건축 이미지를 사용하지 않고 흑백·회색으로 영역과 행동의 위계만 표현합니다. 기존 기업 홈페이지 스타일은 불러오지 않습니다.
2. **내용 목록:** 헤더, 사이드바, 검색, 전체·미완료·완료 필터, 내용과 완료 상태, 등록, 수정, 삭제, 필수 입력, 취소, 삭제 대상, 빈 목록·검색 결과 없음 안내를 배치했습니다.
3. **사용자 과제:** 목록은 검색 → 필터 → 항목 탐색의 순서입니다. 등록·수정은 제목 → 필수 내용 → 저장·취소 순서입니다. 삭제는 대상 확인 → 결과 안내 → 확정·취소 순서입니다.
4. **영역:** Desktop은 240px 사이드바와 유동 작업 영역입니다. Mobile은 헤더 메뉴와 단일 열을 사용합니다. 검색·필터도 세로로 배치해 375px에서 작업 영역을 확보합니다.
5. **위계:** 페이지 제목 32px, 영역 제목 24px, 내용 16px, 메타 정보 12px입니다. 요청에 따라 목록의 상태 변경·수정·삭제를 버튼으로 표현합니다. 취소·탐색은 링크로 구분합니다.
6. **간격:** Desktop 작업 영역은 패딩·섹션 간격 32px, Mobile은 24px입니다. 내부 그룹은 16·12·8px를 사용하며 컨트롤의 기준 높이는 44px입니다.
7. **리듬:** 제목과 도구는 여유 있게, 목록은 반복 행으로 밀도 있게 표현했습니다. 최초 빈 목록에는 등록 동작을, 검색 결과 없음에는 조건 초기화를 제공합니다.

## 표현 범위

- 모바일의 기본 사이드바는 접힌 상태이며 별도 화면에서 펼침 구조를 확인합니다.
- 삭제 확인은 목록 위 모달로 구현할 설계입니다. 기본 JSON 스키마는 절대 위치나 오버레이를 지원하지 않아 중심 배치와 `_solves` 주석으로 나타냈습니다. 모바일 사이드바의 실제 서랍 오버레이도 구조와 주석으로 표현합니다.
- JSON 주석에는 필수 입력, 공백 검증, 기존 완료 상태 유지, 목록 복귀 시 검색·필터 유지, 모달 포커스·Escape 동작을 기록했습니다. 미리보기에서 실제 앱 동작을 수행하는 것은 아닙니다.
- 기본 템플릿은 JSON 패널, 노드 편집, 같은 부모 안의 재정렬, 복사·다운로드·파일 저장 도구를 포함합니다. 파일 저장은 지원 브라우저와 권한에 따라 달라집니다. 이 도구들의 실제 브라우저 동작은 이번 환경에서 검증하지 못했습니다.

## 검증

`validation-report.json`에 기계 판독 가능한 결과를 저장했습니다.

정적 검증 **PASS**:

- 13개 JSON/HTML 쌍: Desktop 6개, Mobile 7개
- 331개 노드의 이름, 컨테이너 방향, 요소 유형
- 텍스트·링크·버튼의 고정 너비 금지, 입력 요소의 높이·유동 크기
- 간격 스케일과 패딩·간격 관계
- JSON과 HTML 내 삽입 데이터의 일치
- 인라인 JavaScript 13개의 구문 검사
- 회색 CSS와 흑백 강제 표시
- 외부 스크립트·스타일·이미지 의존성 없음
- 미리보기 내 React 의존성 없음
- 목록 3개 화면의 모의 DOM 동작 검사: 상태 양방향 전환, 화면·JSON 갱신, 포커스 복원, 수정·삭제 화면 이동

브라우저 렌더링 검증 **미완료**: Chrome headless 실행이 Windows `CreateFile` / `mojo platform channel`의 접근 거부 오류(0x5)로 종료됐습니다. 따라서 실제 픽셀 배치, 텍스트 넘침, 드래그, 저장 기능의 브라우저 검증이나 스크린샷 통과를 주장하지 않습니다.

## 재생성과 재검증

프로젝트 루트에서 실행합니다. Node.js 외 추가 패키지는 필요하지 않습니다.

```sh
node docs/wireframes/generate.mjs
node docs/wireframes/validate.mjs
```

재생성하면 생성된 JSON·HTML이 덮어써집니다. 편집기로 수정한 결과를 유지하려면 먼저 별도 파일로 저장하세요.
